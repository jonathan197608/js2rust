二、转译器 Bug 发现

Bug #1: export const assert = { ... } 对象字面量被静默丢弃

严重性: P0 — 导致所有使用 assert.sameValue() 的测试无法通过 Zig 编译

现象:

  • runtime.js 中 export const assert = { sameValue: assert_same_value, ... } 被转译器处理但未生成对应的 Zig 代码
  • 生成的 runtime.zig 只有 pub fn assert_same_value 和 pub fn assert_not_same_value，缺少 pub const assert = .{ .sameValue = assert_same_value, ... }
  • 测试文件中 const assert = runtime.assert; 引用了一个不存在的定义

修复方案: 在 ExportNamedDeclaration → VariableDeclaration 路径中，当初始值是对象字面量时，应生成 Zig 的匿名结构体 .{ .key = value }

3.2 仅含 new Test262Error() 的测试 (37个)

这些测试的核心逻辑正确转译，只是 throw new Test262Error(msg) 生成了 @compileError。

示例转译结果 (S11_6_1_A4_T1.zig):

pub fn test262_...() !void {
    if ((js_uri.isNaN((std.math.nan(f64) + 1)) != true)) {
        _ = @compileError("Unsupported NewExpression: new Test262Error() (at 14:13)");
        return error.JsThrow;
    }
}

分析: NaN、Infinity、isNaN()、+ 运算符全部正确转译。唯一缺失的是 Test262Error 构造函数。

建议: 在 call.rs:944-948 中将 new Test262Error() 路由到 js_error.JsError.init(message) 而非 @compileError

  • 重试 10 次 — 一致性失败
  • 使用 zig build-lib 替代 zig build — 同样失败
